    Web Map

    A file-by-file mental model of web/, for anyone (or any chat) picking up web work. It answers "where does it live". For "what can it do" read the Web Capabilities section of feature-list.md, for the API read api-contract.md, for visual rules read design-guide.md, and for history and decisions read BUILD_LOG_FRONTEND.md.

    1. Stack and tooling

    • Next.js 16 App Router (Turbopack), React 19, JavaScript (no TypeScript), Tailwind v4 (CSS-first, no tailwind.config.js), lucide-react 1.23 icons, marked plus sanitize-html for Markdown, Plus Jakarta Sans through next/font (self-hosted). No third-party component library.
    • Deployed on Vercel. The browser never talks to Django directly.
    Script What it does
    npm run dev, build, start Standard Next.js scripts
    npm run lint ESLint (two rules are off on purpose, see eslint.config.mjs)
    npm run check:structure scripts/check-structure.mjs: no route files outside app/, no component files inside app/, every lucide icon name must exist
    npm run check lint plus structure check. Run npm run check && npm run build before every PR
    scripts/codemod-primitives.mjs One-off migration to ErrorMessage and the form controls. Dry run by default, --write applies. Safe to re-run

    2. Environment variables

    Name Where Consumers Purpose
    BACKEND_API_URL server only app/api/backend routes Backend /api/v1 base, no trailing slash
    NEXT_PUBLIC_SITE_URL build and server lib/api.js, metadata, sitemap, robots, OG Public origin, also used for server calls to the app's own proxy
    NEXT_PUBLIC_GOOGLE_CLIENT_ID browser GoogleLoginButton Google Identity Services client id
    NEXT_PUBLIC_PLATFORM_ACCOUNT_ID browser lib/platformAccount.js Comma-separated user ids that get the platform badge (optional)

    NEXT_PUBLIC_* values are baked in at build time, so changing one needs a redeploy.

    3. Architecture and data flow

    Browser -> Next route handler /api/backend/[...path] -> Django /api/v1/...
    • Tokens live only in httpOnly cookies, never in browser-readable code. The route handler attaches Authorization, retries once after a refresh and rotates the cookies.
    • Refresh: lib/refreshSession.js keeps one in-flight refresh per refresh token and remembers the result for 10 seconds, so concurrent 401s share one refresh. Cookies are cleared only on a definitive 400 or 401 from the refresh endpoint, never on 429, 5xx or a network failure. Backend unreachable returns 503 { "error": ... }.
    • Client components call clientFetch (lib/clientApi.js). It throws an Error carrying status, fields (the raw DRF body) and friendly copy for network failure, 429 and gateway errors.
    • Server components call apiFetch (lib/api.js), which forwards the request cookies to the app's own proxy through NEXT_PUBLIC_SITE_URL.
    • Events: a 401 anywhere dispatches auth:expired and AuthProvider logs the UI out. lib/locationEvents.js patches history.pushState and replaceState to emit app:locationchange, because a Next <Link> that only changes the hash fires neither hashchange nor popstate.
    • Known limits: a race between two serverless instances can cause a stray logout, and a token refresh during a server render cannot reach the browser until its next request.

    8. Permissions on the client

    • Roles come from useAuth().user: is_admin, moderator_for[], representative_for[] (hub_id plus school). Hiding a control is UX only, the backend enforces everything.
    • canEscalate(user, hubId) in EscalateButton.js is the one check for escalation. Lock, moderation tabs and department management derive from the same fields.
    • refreshUser() must run after an admin changes a hub's status, because /users/me/ lists only active hubs.

    9. Conventions

    • Lists: status loading | ready | error, first page in an effect with a cancel or request-id guard, "View more" appends (dedupe by id when order can shift), load-more errors shown under the button, empty state through EmptyState, count line "N things".
    • Forms: FormField plus Input, Select or Textarea (label tied to control, inline error). Backend field errors through fieldErrorsFrom. No raw red paragraphs, use ErrorMessage.
    • Modals (Report, Escalate, SchoolForm, PageForm, RequestHub) are controlled, z-modal, with no shared Modal primitive yet.
    • Tokens: --color-border dividers, --color-border-strong controls, text-muted for all secondary text (never text-gray-400 or 500), --color-accent #3454D1. Stacking utilities: z-dropdown 20, z-sticky 30, z-overlay 40, z-drawer 50, z-modal 60, z-toast 70, z-progress 100. Never raw z numbers. See design-guide.md.
    • Client API: always clientFetch, never fetch to the backend from the browser.

    10. Behaviours that are easy to get wrong

    • SOLVED means "has a best answer". Only is_locked blocks new answers.
    • Question and school URLs are UUID plus a cosmetic slug, the slug is never used for lookup.
    • Notification and report links come from link_target, null means no link.
    • Reports are private: /my-reports only, never on the profile, never reviewer or escalation data.
    • router.refresh() updates server props but never resets a client component's own state, reset loading state explicitly after a success.

    11. How to add things

    • New page: file under app/, metadata through export const metadata or generateMetadata. If it needs client state, make a thin server wrapper plus a client component.
    • New list: copy HubQuestionList's loading pattern, use EmptyState and ErrorMessage.
    • New API call: through clientFetch (client) or apiFetch (server).
    • New icon: import from lucide-react, npm run check:structure verifies the name.
    • New notification type: add its icon to the NotificationItem icon map, and to the mobile client.

    12. Known gaps

    See "Known gaps" in the Web Capabilities section of feature-list.md: hub-offline notice for moderators (needs backend), shared Modal primitive, label wiring in SchoolFormModal and PageFormModal, windowed "View more" lists, and optional stronger control borders.

    13. Keeping this file current

    Regenerate the tree and exports after any file move, new route or new shared primitive:

    find app components lib scripts -type f \( -name "*.js" -o -name "*.mjs" \) | sort
grep -rnE "^export (default )?(async )?function " app components lib --include=*.js
