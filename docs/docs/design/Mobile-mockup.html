Notes:

1. How to read this file
  • The phone is the spec. Match layout, spacing, copy and states. The viewer controls above it (Preview as, UI state, dark, restart) exist only to show every role and state.
  • Search the HTML for AGENT NOTE for design decisions. The API contract wins over this mockup if they disagree, leave a note in BUILD_LOG_MOBILE.md.
  • Icons are Font Awesome here. Use your platform's equivalent icon set, keep the same meanings.
2. Design tokens (copy these)
  • Accent #3454D1. Success #1D8A6C (dark #3FBF97). Danger #CE4747. Font Plus Jakarta Sans 400 to 800.
  • Light: bg #FBFAF8, ink #16140F, line #E5E3DF, strong (control borders) #CFCBC2, muted #67645C, surface #FFFFFF.
  • Dark: bg #16171C, ink #F5F3EE, line #2C2D34, strong #3A3B44, muted #9EA1AB, surface #1E2939.
  • Use "muted" for ALL secondary text, never raw grays (contrast checked 4.5:1 on every surface). Light and dark must both work, and follow the system theme by default.
  • Shape: rounded-lg for buttons and cards, rounded-full only for search pills and avatars. Minimum touch target 44pt.
3. Navigation and roles
  • Tabs: Home, Schools, Ask (raised), Alerts (unread badge), Profile. Search icon sits in the top bar. The drawer holds Tags, Search, My reports, Policies and guides, and staff web links.
  • Roles: guest, student, moderator, admin. Derive from GET /users/me/ (is_admin, moderator_for, representative_for). Guests browse freely and get the sign-in sheet on any action.
  • Staff scope is strict. No moderation or admin screens in the app. Staff get lock, escalate and report in context, and "Open on web" buttons that open the SYSTEM browser. See the staff section of the prompt.
  • Deep links: notifications and reports carry link_target. Open the question and scroll to answer_id. null means no link.
4. States every screen needs
  • Loading skeleton, empty (icon, title, one line), error with Retry, offline banner with cached content. Use the UI state control to preview.
  • Friendly copy: no network, 429 "You're going a bit fast", 502/503/504 "taking too long", other 5xx. 400 field errors go under the field.
  • Pull to refresh on lists. Load more appends and dedupes by id. Ignore stale responses when filters change.
5. Screen to endpoint map
  • Login: POST /auth/google/. 403 suspended, 401 invalid token.
  • Home: GET /questions/?ordering=-created_at, /schools/?has_hub=true&page_size=5, /tags/?popular=true&page_size=8.
  • Search: GET /search/questions/?q=&tag=&page= (results include slug).
  • Schools: GET /schools/ with search, has_hub, institution_type, ownership, state, page.
  • School: GET /schools/{id}/, /hubs/by-school/{id}/ (404 means no hub), /questions/?hub=&status=&department=&ordering=, POST /hubs/activation-requests/.
  • Tags: GET /tags/ (paginated), /tags/{name}/questions/.
  • Question: GET /questions/{id}/. Follow: POST and DELETE /questions/{id}/follow/. Lock: POST and DELETE /questions/{id}/lock/. Answers: POST /answers/, PATCH and DELETE /answers/{id}/, POST and DELETE /answers/{id}/vote/, POST /answers/{id}/mark-best/. Comments: GET /answers/{id}/comments/, POST /comments/, PATCH and DELETE /comments/{id}/. Reports: POST /reports/, POST /reports/{id}/escalate/.
  • Ask: GET /schools/?has_hub=true, /hubs/by-school/{id}/ (departments), /tags/?search=, POST /questions/.
  • Alerts: GET /notifications/, POST /notifications/{id}/mark-read/, POST /notifications/mark-all-read/.
  • Profile: GET and PATCH /users/me/, GET /questions/?author=, /users/me/answers/, /users/me/comments/.
  • My reports: GET /reports/mine/?status=. Pages: GET /pages/ and /pages/{slug}/.
6. Rules that are easy to get wrong
  • SOLVED means "has a best answer", it does not close the question. Only is_locked blocks answers. Only the question's author marks best. Nobody votes on their own answer.
  • Bodies are Markdown, render safely. Question URLs use the id, the slug is cosmetic.
  • Reports are private both ways. Never show the reviewer or escalation state to a reporter.
  • Rate limits return 429. Tokens rotate on refresh, share one refresh promise, clear tokens only on a definitive 400 or 401.
  • Out of scope for this MVP: moderation, admin, hub offline controls, static page editing, windowed lists, push notifications (later).
