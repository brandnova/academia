    Mobile Client Map

    A file-by-file mental model of mobile/, for anyone (or any chat) picking up mobile work. It answers "where does it live". For "what can it do" read the Mobile Client section of feature-list.md, for the API read api-contract.md, for visual rules read design-guide.md, for history and decisions read BUILD_LOG_MOBILE.md, for regression checks TESTING.md, for launch work DEPLOYMENT_CHECKLIST.md. The UX reference is design/Mobile mockup.html.

    1. Stack and tooling

    • React Native 0.88.1, React 19.3.0, Expo SDK ~58, TypeScript ~6.0.3. Navigation: React Navigation 7 (native stack, bottom tabs) plus a custom slide-over drawer. Icons: FontAwesome6 through @expo/vector-icons. Font: Plus Jakarta Sans 400 to 800 (@expo-google-fonts/plus-jakarta-sans).
    • Native modules: expo-secure-store, expo-network, expo-splash-screen, expo-linking, expo-constants, expo-font, @react-native-google-signin/google-signin (native Google sign in). Web preview only: react-native-web, expo-auth-session, expo-web-browser.
    • No state library. Plain React context providers plus two data hooks (useQuery, usePagedList).
    • Builds: eas.json has development, preview (APK) and production profiles. The env block of a profile holds the public EXPO_PUBLIC_* values, EAS never reads .env.
    Script What it does
    npm start, android, ios, web Expo dev server (npx expo start -c clears the cache)
    npm run typecheck tsc --noEmit
    npm run export:web Production web export check
    npx expo-doctor Dependency and config health
    npx expo export --platform android Proves the JS bundles (pre-flight before a build)
    npx expo prebuild --platform android --no-install --clean Validates app.json and config plugins, then rm -rf android
    brand/make-brand-assets.sh Generates every icon, splash and brand PNG (repo root)

    2. Environment variables

    Name Consumer Purpose
    EXPO_PUBLIC_API_URL src/api/config.ts API base including /api/v1. Derived from the Metro host when blank (Expo Go). Required in builds
    EXPO_PUBLIC_WEB_BASE_URL src/config/app.ts Share links and the staff web handoff
    EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID, EXPO_PUBLIC_GOOGLE_CLIENT_ID src/auth/GoogleSignInButton.tsx Web OAuth client, used for web sign in and to configure the native library
    EXPO_PUBLIC_GOOGLE_IOS_CLIENT_ID GoogleSignInButton.tsx iOS client (iOS untested)
    EXPO_PUBLIC_PLATFORM_ACCOUNT_ID src/config/app.ts Comma separated user ids that get the official "A" badge (per database)
    EXPO_PUBLIC_SUPPORT_EMAIL src/config/app.ts Shown with the suspended-account message
    EXPO_PUBLIC_DEV_MODE src/config/app.ts Developer access sheet, honoured only when __DEV__
    EXPO_PUBLIC_DEV_ACCESS_TOKEN, _REFRESH_TOKEN AuthProvider.tsx Optional seeded dev login, __DEV__ only

    EXPO_PUBLIC_* values are baked in at build time, so changing one needs a rebuild. The Android OAuth client has no variable: Google matches it by package name and signing SHA-1.

    3. Architecture and data flow

    • Direct API. The app calls Django at /api/v1 with no proxy. Native requests have no CORS. src/api/client.ts attaches the bearer token to every request (also public reads, so user_vote and is_following are personalised), enforces timeouts, and turns failures into ApiError (status, fields, network).
    • Session. Tokens live in expo-secure-store (localStorage on web). A 401 triggers one shared refresh. The session is cleared only on a definitive 400 or 401 from /auth/refresh/. Network failure, 429 and 5xx keep the session and start from the cached user.
    • Guests and the auth gate. Guests browse freely. requireAuth(action) opens one sign-in sheet that keeps the screen and resumes the action after login. The Login screen is a one-time welcome.
    • Roles. useCapabilities() is the only place roles are derived. Hiding a control is UX, the backend enforces everything. The mobile client has no moderation or admin screens: staff get lock, report and escalate in context and "Open on web" handoffs that never carry a token.
    • Lists. usePagedList (paged, deduped, stale-guarded, pull to refresh, View more with its own error). useQuery for single resources.
    • Google. Native: Google account picker, access token to POST /auth/google/. Web: browser token flow.

    5. Navigation, routes and deep links

    Files in src/navigation/: types.ts (param lists, navigationRef, navigateRoot, startAsk), RootNavigator.tsx (stack, theme, linking), TabNavigator.tsx, TabBar.tsx (Home, Schools, raised Ask, Alerts with unread count, Profile), Drawer.tsx and DrawerProvider.tsx (swipe left, Back or backdrop closes), linking.ts.

    Route Params Notes
    Main tabs Home, Schools, Ask, Alerts, Profile Ask params: nonce, hubId, schoolId, schoolName, editQuestionId
    Login none Shown to a first-time guest and after logout
    School schoolId?, slug?, name? UUID or slug
    Question questionId, answerId? answerId scrolls to and flashes that answer
    Search, Tags, MyReports, Pages none
    TagQuestions tag
    PageView slug, title?

    Deep links (linking.ts): prefixes academiaatlas://, the Expo dev URL and WEB_BASE_URL. Paths mirror the web: questions/:id/:slug?, schools/:id/:slug?, tags/:tag, pages/:slug, search, tags, my-reports, notifications, schools, profile. A #answer-{id} suffix opens the question at that answer. https links in the app need Android intent filters with autoVerify and assetlinks.json (launch work).

    13. Conventions

    1. Lists: usePagedList, FlatList with RefreshControl, ViewMoreButton in the footer, skeleton while loading, EmptyState when empty, ErrorState with retry.
    2. Forms: Field plus fieldError(err, name). Never show raw error objects.
    3. Sheets over modal screens. Never stack Modals: switch the content of one sheet by mode.
    4. Colours only through useTheme() tokens, never hex (white on accent excepted).
    5. Roles only through useCapabilities().
    6. Restricted actions through requireAuth, never a redirect to Login.
    7. Screens with inputs wrap in KeyboardAvoid, keyboard state only from useKeyboard.
    8. Reuse: a block used twice, or one that pushes a screen past a few hundred lines, becomes a component.
    9. User content only through Markdown and MarkdownEditor, new formatting goes in lib/markdownEdit.ts.
    10. Author names always carry PlatformBadge.
    11. Suggestion lists render inline under the field, not as popovers.
    12. Reports through ReportForm only.
    13. No em dash characters in code, comments or docs.

    14. Behaviours that are easy to get wrong

    • SOLVED means "has a best answer". Only is_locked blocks new answers. Only the question author marks best.
    • Reports are private: /my-reports only, no reviewer or escalation data, never on the profile.
    • Notification and report links come from link_target, null means no link.
    • A failed refresh must not log the user out unless it was a definitive 400 or 401.
    • Vote switching updates the UI after each confirmed server step.
    • Heading syntax renders as plain text everywhere except static pages.
    • Preview and production builds contain no developer sheet and no seeded tokens (__DEV__).

    16. How to add things

    • New screen: add the file in src/screens/, a route and its params in navigation/types.ts, register it in RootNavigator.tsx, add a path in linking.ts, and add its row to section 6.
    • New API call: add it to endpoints.ts (user client only), type it in types.ts, use useQuery or usePagedList.
    • New notification type: add its icon to NotificationsScreen, and to the web client.
    • New env variable: read it in config/app.ts, add it to .env.example, eas.json and section 2.

    17. Known gaps

    See "Known gaps" in the Mobile section of feature-list.md: sheet swipe down, offline cache, https app links (launch), VoiceOver and all iOS checks (untested), native Google sign in verification on the final build.
