    Design Guide

    The visual and interaction rules for Academia Atlas on web and mobile. Shared rules come first, then web and mobile specifics. Component and file locations are in frontend-map.md and mobile-map.md.

    Product and roles

    Academia Atlas helps students ask academic questions specific to their school and preserves useful answers for future students. It is a searchable reference platform, not a social feed.

    Role Capabilities
    Guest Browse and search schools, hubs, questions and answers. Cannot post, vote or comment
    User Guest capabilities, plus ask, answer, comment, vote, follow, request a hub, report content and receive notifications
    Moderator User capabilities, plus an unanswered queue for assigned hubs, lock and unlock, escalate
    School Representative User capabilities, plus department management and moderator assignment for their hub, lock and escalate
    Admin Manage schools, hub requests, representatives, reports, users, tags and static pages

    The API contract defines the role fields. The backend is authoritative for every permission.

    Principles

    • Function over decoration. Finding and contributing knowledge, not marketing.
    • Search before social. Browsing and filtering are the main navigation.
    • Content first. Questions and answers are the interface, metadata is small and muted.
    • Accessible by default. Visible focus, adequate contrast, and status is never conveyed by color alone: icons are paired with text.
    • Light and dark are equal. Neither theme is an afterthought.
    • Friendly failure. Every list and detail view handles loading, empty, error and populated states, with human copy.

    Color tokens

    One accent, otherwise restrained and warm neutral. Both surfaces use the same values.

    Token Light Dark Use
    bg #FBFAF8 #16171C Page and chrome background
    ink #16140F #F5F3EE Primary text
    border (line) #E5E3DF #2C2D34 Dividers, card edges
    border-strong #CFCBC2 #3A3B44 Form control and outlined button borders only
    muted #67645C #9EA1AB ALL secondary text
    surface #FFFFFF #1E2939 Inputs, cards, popovers, sheets
    accent #3454D1 #3454D1 Links, primary actions, focus ring, selected state
    success #1D8A6C #3FBF97 Solved state, confirmations
    danger #CE4747 #CE4747 Errors and destructive actions (web red scale is overridden to a clean red, 600 is #B93D3D)

    Rules: - Muted is measured at 4.5:1 or better on every surface the app uses (about 5.7:1 on the page background). Never use raw grays for secondary text. - Control borders measure about 1.6:1, below WCAG 1.4.11's 3:1. This is a deliberate design trade-off. If stronger edges are wanted, retune only border-strong (candidates: light #8F8B80, dark #6B6D7A). - Tailwind's default gray scale is left untouched on web, and used for chips and hovers.

    Brand and app icons

    The logo is a blue "A" with a gold swoosh and four-point star. The blue is the UI accent #3454D1 and the gold is about #FFB000 (sample from the master). Gold appears only in the logo, app icon, splash and store graphics. The wordmark is "Academia" over "Atlas", the short form for tight spaces is "A-Atlas" (launcher label). Masters live in brand/src (mark-source, icon-source, tile-source, circle-source) and every PNG is generated by brand/make-brand-assets.sh. Icon rules: iOS icon opaque and square with no baked corners, Android adaptive mark inside the 61% safe zone on the accent background, monochrome icon a single-colour silhouette with a gap between the A and the swoosh.

    Typography

    Plus Jakarta Sans, weights 400 to 800, one family. Hierarchy comes from weight and size, not from extra families. Body 14 to 15px, meta 11 to 12px, page titles 20 to 30px extra-bold. Markdown content has its own typography (lists, quotes, code, headings only on static pages).

    Shape, spacing and layout

    • Corners: standard radius for buttons, inputs and chips, a larger radius for cards, answer blocks and modals. Pill shape only for search bars. Circles only for avatars and count badges.
    • Lists are dividers, not cards: divide-y rows with a top and bottom border.
    • Web widths: main column max-w-5xl with px-4, question page max-w-3xl, forms max-w-2xl. Two-column layouts (filter sidebar plus list) start at md. The floating Ask button appears below sm.
    • Status is always icon plus label: open is an empty circle in muted, answered is a message icon in accent, solved is a check circle in success. Locked adds a lock in danger.

    Components and patterns

    • Forms: label above the control, small and muted. Error under the field in danger. Backend field errors map to their own field. Sizes xs, sm, md, lg.
    • Messages: errors and warnings use one component with role alert. Empty states have an icon, a title and one line, never just gray text.
    • Menus: secondary actions (edit, delete, report, escalate, share) live in a kebab menu. Follow, vote and mark-best stay inline.
    • Confirmations: destructive actions confirm inline or in a small dialog, never silently.
    • Tabs scroll instead of wrapping and support arrow keys.
    • Platform badge: a small "A" mark next to the official account's name, tap to explain.
    • Markdown: all user content renders through one safe renderer.

    Motion and feedback

    Subtle and CSS-only. Buttons scale to 0.97 on press with 150ms transitions. Skeletons shimmer. Lists fade up with a short stagger, and rows added by "View more" animate on their own. The answer deep-link flash honors reduced motion. A global 2px accent focus ring with a 2px offset shows on keyboard focus.

    Stacking (web)

    z-dropdown 20, z-sticky 30, z-overlay 40, z-drawer 50, z-modal 60, z-toast 70, z-progress 100. New overlays pick a level, never a raw number.

    Theming

    Class-based dark mode. Web has a manual toggle in the top bar, persisted. Mobile follows the system by default with a manual override. Both must be checked on every change.

    Page states

    Every list or detail view handles loading (skeleton), empty, error with retry, and populated. Also: offline (mobile), expired session, and friendly copy for no network, 429 ("You're going a bit fast"), gateway timeouts and other 5xx. A 400 shows its message under the field.

    Web direction

    A structured, searchable reference tool. Compact question rows, prominent search on browsing pages, persistent filters in a sidebar that collapses on narrow screens. Top bar with wordmark, theme toggle, notification bell and profile menu. A sidebar drawer for navigation at every width. A homepage hero with a full-bleed background and a legibility scrim. Lucide icons.

    Mobile direction

    Follows design/Mobile mockup, same tokens and typography. What differs from web:

    Area Web Mobile
    Navigation Top bar plus overlay sidebar Bottom tabs (Home, Schools, Ask, Alerts with badge, Profile) plus a slide-over drawer
    Home school cards Side card list Horizontal strip of cards (tile, large question count, names, location)
    Google sign in Google Identity Services popup Native account picker (no browser redirect)
    Ask action Floating pill below sm, plus buttons on pages Raised centre tab
    Secondary actions Dropdown kebab menu Bottom sheet
    Modals Centered dialogs Bottom sheets, under 80% height, backdrop tap and swipe dismiss
    Sheets Centered dialogs Bottom sheets, backdrop tap and Back dismiss, swipe down planned
    Filters Collapsible sidebar Horizontal chips and a filter sheet
    Touch targets Pointer sized At least 44pt, bigger toolbar buttons in the editor
    Corners Standard and large radius 8pt controls, 12pt FAB, 16pt sheet tops
    Icons Lucide Font Awesome 6 equivalents, same meanings
    Avatars Not rendered Google photo with initial fallback
    Theme Manual toggle System by default, override in profile and drawer
    Feedback Hover and focus states Pressed states, pull to refresh, offline banner, reduced motion respected, text scaling capped at 1.4
    Links Web URLs academiaatlas:// scheme, https links when set up, same paths as the web
    Keyboard n/a Composer and sheets stay above the keyboard
    Staff tools Full moderation and admin screens None. Lock, escalate and report in context, plus "Open on web" buttons that open the system browser
    Menu Slide-over drawer, closes on backdrop, Back or swipe left Sidebar overlay with Escape and backdrop
    Offline Banner "Content may be out of date" until an offline cache exists n/a
    Crash Friendly error boundary with Try again error.js pages

    URL conventions

    School and question URLs use UUIDs as the lookup key and may append a human-readable slug, for example /schools/{id}/{slug} and /questions/{id}/{slug}. The slug is cosmetic and may be omitted. schoolUrl() and questionUrl() keep links consistent on web. Mobile looks up by id and builds share links with the same pattern.

    What not to build yet

    • School reviews or ratings
    • School verification badges or "claim your school" flows
    • Subscription or payment UI
    • A public API developer portal

    If review or monetization work is designed later, paid features must never hide or suppress legitimate negative reviews.
