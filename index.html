    Academia Atlas

    A school-focused academic knowledge platform that helps students find answers, solve academic problems, and preserve institutional knowledge in a searchable, organized way. It is launching first with Nigerian tertiary institutions, where the problem originated, and is built to extend to other countries.

    Student is confused. Student asks a question. Student gets an answer. Future students find that answer without asking again.

    The problem

    Every semester, students ask the same questions: how to calculate a GPA, what clearance needs, how registration works, what to expect during SIWES, what happens after a missed deadline, how to change department. The answers exist, but they are scattered across WhatsApp groups, Telegram channels and private conversations, and they disappear when older students graduate.

    The solution

    A structured platform where academic questions are asked, answered, searched and preserved, organized by school and department, instead of buried in temporary chats.

    Core principles

    • One hub per school.
    • Schools are platform-managed records.
    • Knowledge is more important than engagement metrics.
    • Search comes before social features.
    • Information should become easier to find over time, not harder.

    Surfaces

    Surface Stack Notes
    Backend Django REST Framework, PostgreSQL, SimpleJWT with Google sign in Pure versioned JSON API at /api/v1/
    Web Next.js (App Router), Tailwind v4, deployed on Vercel Full product including moderation and admin tools
    Mobile Expo (React Native, TypeScript) User client. Staff open the web tools in the browser

    Development philosophy

    API first. Behavior, data structures and API responses are documented and agreed before implementation, and each surface is built against the same contract. Documentation is a development artifact, not an afterthought.

    Current status

    Phase: post-MVP, pre-launch.

    • Backend: complete (15 MVP phases plus the post-MVP maintenance backlog), live on Vercel with Supabase Postgres and Upstash Redis. A PythonAnywhere deployment remains as the preview and testing backend.
    • Web: MVP and the eight-batch audit pass are complete and live.
    • Mobile: MVP built, post-MVP audit complete. See the Mobile section of the Feature List and the Mobile Build Log.

    Next steps

    1. Do a repo cleanup.
    2. Work through the Deployment Checklist for backend, web and mobile.
    3. Onboard initial moderators and school representatives.
    4. Open the platform to real users.
