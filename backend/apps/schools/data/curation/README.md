# School directory curation

This directory holds the school-directory preparation scripts and human-review
artifacts. The production import inputs remain in `../imports/`; do not copy
those files here.

## Provenance and licence

The prepared source-record CSVs identify three regulator sources, all recorded
with a fetch date of 2026-09-04:

- NUC: <https://www.nuc.edu.ng>
- NBTE: <https://digitalnbte.nbte.gov.ng>
- NCCE: <https://ncce.gov.ng>

The regulator source lists themselves are not included here. The copies in the
private working directory do not consistently identify their source URL or
fetch date in a header, and some include named officials. Do not add them here
until provenance is recorded and the files have been checked for personal
contact information and copied page prose. The third-party NYSC cross-reference
is also excluded because redistribution terms have not been verified. No
source-specific data licence has been confirmed; treat the regulator material
as source data whose reuse terms still need review, rather than assuming it is
openly licensed.

## Files and decisions

- `scripts/normalize_and_flag.py` parses regulator lists, normalizes institution
  records, and reports possible duplicates for human review. It does not merge
  records automatically.
- `scripts/dedupe_and_prepare.py` applies explicit merge and field-patch
  decisions to the prepared CSV inputs and writes the final import CSVs.
- `merges_applied.csv` is the available audit ledger for manual merge decisions.
  It currently records two merge rows, while the finalization script contains
  additional hard-coded merge and field-patch decisions. The audit ledger is
  therefore incomplete; reconcile it before treating it as the full decision
  history, and keep it complete whenever decisions are revised.
- `flags_report.csv` is the broader review backlog. It differs from
  `imports/known_possible_duplicates.csv`, which remains the import-time
  duplicate reference.

`schools_normalized.csv` is an intermediate generated by the first script and
is intentionally not stored here.

## Run order and current limitations

The scripts are preserved verbatim from the private curation workspace. They
use paths relative to the current working directory, not to the script file.
From the repository root, use a disposable working directory so generated
files do not overwrite the private originals:

```sh
repo_root="$PWD"
workdir="$(mktemp -d)"
cp -R "gitignore/School data/Nig. Tertiary Institutions" "$workdir/"
cp "gitignore/School data/schools_ready_for_import.csv" "$workdir/"
cp "gitignore/School data/source_records_ready_for_import.csv" "$workdir/"
(cd "$workdir" && python "$repo_root/backend/apps/schools/data/curation/scripts/normalize_and_flag.py")
```

Review `flags_report.csv` and record decisions; do not infer merges from
similarity scores. The finalization script expects
`schools_ready_for_import.csv` and `source_records_ready_for_import.csv` in the
same working directory:

```sh
(cd "$workdir" && python "$repo_root/backend/apps/schools/data/curation/scripts/dedupe_and_prepare.py")
```

The intermediate ready-for-import files and raw lists are not included in this
curation directory, and the step that prepares those ready files is not
provided here. For the commands above, the ready files are copied from the
private workspace. In the current backend, the importer reads
`imports/schools_final.csv` and `imports/source_records_final.csv`; those are
not byte-identical to the private ready-for-import files. Therefore this
repository does not yet contain a fully reproducible end-to-end source-to-import
pipeline. Resolve that gap before treating a fresh run as a replacement for the
current imported dataset.

## Re-verification

Re-fetch the regulator lists, record the source URL and retrieval date for each
file, and check the source's reuse terms. Compare the refreshed records with the
current import set, review every reported candidate manually, and preserve
decisions in `merges_applied.csv`. Do not overwrite the production import CSVs
until the review is complete and the resulting dataset has been validated.
